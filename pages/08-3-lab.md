# 08-3. [종합 실습 Lab] 골든타임 SOS 긴급 구조 및 위치 전송 관제 모달

앞서 배운 실시간 고정밀 GPS 측정 기능(`08-1`)과 비상 연락망 다중 SMS 브로드캐스트 및 백엔드 로깅(`08-2`)을 하나로 결합하여, 사이렌 버튼 클릭 시 즉시 팝업되는 통합 SOS 응급 관제 모달 시스템을 완성합니다.

---

## 1. 🎯 학습 목표
1. 실시간 GPS 좌표 획득과 모바일 모달 팝업의 시각적 UI 상태를 동기화할 수 있습니다.
2. 여러 보호자의 전화번호 목록을 동적으로 파싱하여 다중 SMS 링크와 연동합니다.
3. 긴급 문자 발송 직후 백엔드 `emergency_logs` 테이블에 좌표 정보가 즉시 저장되는 전송-기록 파이프라인을 완성합니다.

---

## 2. 💡 핵심 개념

### ① SOS 관제 모달의 원터치 3단계 시퀀스
환자가 공황 상태에 빠져 있더라도 최소한의 터치로 생명을 지킬 수 있도록 최적화된 UX 파이프라인을 구축합니다.

```text
[🚨 상단 사이렌 버튼 클릭]
         │
         ▼
[1단계: GPS 자동 활성화 및 실시간 오차 측정]
         │
         ▼
[2단계: 다중 보호자 원터치 비상 문자 발송 버튼 활성화]
         │
         ▼
[3단계: SMS 실행과 동시에 emergency_logs 백엔드 자동 적재]
```

3. 🛠️ 준비물
Python 3.10 이상 실행 환경
emergency_dispatcher.py 소스 파일
4. 💻 단계별 실습 코드

```python
"""
파일명: sos_modal_lab.py
기능: SOS 비상 관제 모달 데이터 바인딩, 원터치 SMS 생성, DB 로깅 종합 실습
"""

from typing import List, Dict, Any
from emergency_dispatcher import generate_sms_broadcast_url, log_emergency_dispatch


class SOSController:
    """스마트119 SOS 응급 관제 통합 컨트롤러"""

    def __init__(self, user_email: str, user_name: str, guardians: List[str]):
        self.user_email = user_email
        self.user_name = user_name
        self.guardians = guardians

    def trigger_emergency_event(
        self,
        symptom: str,
        latitude: float,
        longitude: float,
        is_ios: bool = False
    ) -> Dict[str, Any]:
        """
        응급 상황 트리거 시 SMS 링크 생성과 DB 로깅을 동시 수행합니다.
        """
        # 1. 원터치 비상 SMS 발송 링크 생성
        sms_url = generate_sms_broadcast_url(
            phone_numbers=self.guardians,
            patient_name=self.user_name,
            symptom=symptom,
            lat=latitude,
            lng=longitude,
            is_ios=is_ios
        )

        # 2. 클라우드 emergency_logs 영구 적재
        db_res = log_emergency_dispatch(
            user_email=self.user_email,
            symptom=symptom,
            lat=latitude,
            lng=longitude,
            recipients=self.guardians
        )

        return {
            "status": "triggered",
            "sms_url": sms_url,
            "google_map": f"https://maps.google.com/?q={latitude},{longitude}",
            "db_logged": db_res.get("success", False),
            "guardian_count": len(self.guardians)
        }


# --- 종합 관제 테스트 실행 ---
if __name__ == "__main__":
    print("=" * 65)
    print("스마트119 종합 SOS 응급 관제 모달 시스템 가동")
    print("=" * 65)

    # 모의 환자 및 보호자 2명 설정
    my_guardians = ["010-5555-1234", "010-7777-5678"]
    controller = SOSController(
        user_email="patient@smart119.local",
        user_name="김영희",
        guardians=my_guardians
    )

    # 환자가 사이렌 버튼을 눌러 GPS 측정 완료된 상황 모의
    event_result = controller.trigger_emergency_event(
        symptom="[AI 응급 감지] 극심한 흉통 및 어지럼증 호소",
        latitude=37.5172,
        longitude=127.0473,
        is_ios=False
    )

    print(f"\n📢 [응급 알림 처리 결과]")
    print(f"- 수신 대상 보호자: {event_result['guardian_count']}명")
    print(f"- 지도 확인 URL: {event_result['google_map']}")
    print(f"- 생성된 SMS 발송 링크:\n{event_result['sms_url']}")
    print(f"- 클라우드 emergency_logs 저장 상태: {'성공' if event_result['db_logged'] else '실패'}")

```

보호자 비상 연락처가 단 한 명도 등록되어 있지 않은 상태(guardians = [])에서 응급 상황이 발생했을 때 시스템이 멈추지 않고 취해야 할 가장 안전한 폴백(Fallback) 조치는 무엇일까요?

휴대폰의 모든 데이터를 초기화한다.
사용자에게 퀴즈를 풀게 한다.

사용자에게 음성(TTS)으로 응급 상황 대처 요령을 안내하는 동안에도, 동시에 백그라운드에서는 왜 클라우드 DB의 emergency_logs 테이블에 위도와 경도, 타임스탬프를 반드시 기록해 두어야 하는지 119 소방관 및 사후 의료 관제 관점에서 서술하시오.
